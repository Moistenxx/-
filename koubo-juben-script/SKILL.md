# 口播剧本 Skill

把用户给出的主题转成“可以拍、可以剪、可以验证”的视频方案。核心结构来自科技米线案例：先让观众看到一个正在发生的结果，再沿着一条可观看的路线展示证据，真人口播只负责反应、解释、个人判断和下一站。

## 使用输入

从用户已有信息中提取：

- 主题/要测试的对象，以及真实任务或场景。
- 平台、目标观众、期望时长、横竖屏；缺失时默认竖屏 90 秒。
- 创作者能提供的素材：真人出镜、屏幕录制、成品、失败版本、现场/生活 B-roll。
- 必须出现的结果、数字、限制和 CTA。缺失项用 `待补` 标记，不编造结果。

如果主题仍然抽象，先把它改写成一句可验证任务：`我把 X 交给 Y，想看看能否完成 Z`。如果没有可验证动作，改成“观点+一个具体例子”，不要伪装成实测。

## 生成流程

1. 从参考文件读取案例风格规则：`references/case-patterns.md`。
2. 选择一个主模板：
   - 实测/作品展示：`结果 → 操作路线 → 细节证据 → 限制 → 结论`。
   - 教程/方法论：`痛点 → 3 个动作 → 每个动作的屏幕证据 → 适用边界`。
   - 观点/经历：`问题 → 外部或个人证据 → 3 个判断 → 反方/限制 → 下一步`。
3. 为视频设计一条“场景路线”，每一站只证明一个卖点；优先使用动作、点击、切换、前后对比或真实失败证明，而不是口头形容。
4. 把口播拆成循环：`即时反应 → 发生了什么 → 为什么重要 → 下一站`。每段 8—15 秒，画面能证明的内容不在口播中重复朗读。
5. 生成逐时间段分镜。时间必须覆盖全片，且画面、口播、字幕、剪辑动作互相对应。
6. 在脚本后给出拍摄清单、画面证据清单、失败/风险点和 CTA。

## 必须输出的顺序

1. **视频定位**：标题候选 3 个、目标观众、核心承诺、视频类型、建议时长和画幅。
2. **一句话任务**：`我把……交给……，验证……`。
3. **内容路线**：入口/问题、至少 3 个场景站点、结果/彩蛋；每站写“动作 + 证明点”。
4. **完整分镜表**：时间、画面/拍摄、口播、字幕关键词、剪辑动作、所需素材。开头 3—5 秒必须出现结果、冲突或正在发生的动作。
5. **口播全文**：按镜头顺序写自然口语；短句、第一人称、连接词清楚，避免播音腔和空泛形容词。
6. **口播逻辑**：用 5—8 个节点解释问题如何推进，标明事实、个人判断和待验证内容。
7. **拍摄执行单**：真人机位、屏幕录制、B-roll、失败版本、结果素材、收音和隐私检查。
8. **剪辑规则**：切镜节奏、字幕层级、画中画/屏幕比例、关键局部放大、音乐进入/退出点。
9. **风险与替代方案**：结果失败、页面加载慢、录屏看不清、数据/隐私、没有成品时分别给补拍或改写方案。
10. **发布文案**：标题、封面一句话、正文结构、一个具体评论问题和 CTA。

## 质量门槛

- 每个重要判断后面有对应画面证据；没有证据就标为“个人判断”或“待验证”。
- 至少保留一次失败、返工、限制或不够生产级的地方；没有真实失败时明确写“需要补拍/补充限制”，不要编造。
- 成品展示优先于技术解释；技术名词必须落到一个动作或观众能看懂的结果。
- 画面路线必须能在没有旁白时看懂大致发生了什么。
- 不复制案例的品牌名、夸张数字或原句，只复用结构和制作方法。
- 如果用户只给主题，没有真实结果，输出“拍摄前验证清单”，并把脚本中的结果句留为占位符。

## 禁止的输出形态

- 只给一段口播，不给画面和拍摄方法。
- 只写“展示界面/展示效果”，不说明具体展示哪个动作、哪个区域和证明什么。
- 把 AI 的预期能力写成已经发生的结果。
- 用大段术语解释替代场景路线、镜头和证据。
