# 案例拉片提炼：科技米线的可复用制作方法

本文件是结构方法参考，不复制具体博主的品牌、原句或标题；只提炼可迁移的脚本和拍摄决策。

## 画面系统

- **作品/实测主画面**：屏幕录制、游戏/网页、成片或产品 UI 占主要面积；尽量保留真实操作路径、鼠标、状态栏、地图或时间线。
- **真人画中画**：固定在左下角或侧边，用来承载即时反应、判断和个人连接，不重复念屏幕文字。
- **字幕**：稳定在底部安全区，短句、白字黑底；关键词可以用黄/绿等强调色。字幕应补充动作结果，而不是逐字转录全部口播。
- **转场**：用地图、目录、弹窗、时间线、页面滚动或下一次点击完成空间转场，少用装饰性特效。

## 三种模板

### A. 作品试玩/产品发布

`最强成品画面 → 第一个可操作动作 → 2—4 个交互证据 → 作品/案例内容 → 兼容性或真实测试 → 彩蛋/结果`

每个站点只解决一个问题：能不能玩、细节够不够、内容是否真实、手机能不能用。口播循环为：`哇/反应 → 发生了什么 → 这证明什么 → 我们去下一站`。

### B. AI 实测/工作流

`任务规模或冲突 → 原始素材/问题 → AI 初步结果 → 人的反馈 → 返工/失败 → 最终结果 → 适用边界`

把操作过程当作剧情。保留一处等待、回滚、错误或第一版不足，证明不是凭空生成。

### C. 教程/观点

`身份痛点或问题 → 3 个判断/动作 → 每段一个页面或截图证据 → 反向限制 → 可执行的下一步`

稳定口播机位可以承载观点，但每个抽象句后面要接一个具体例子、页面或动作。

## 脚本判断规则

1. 先问“观众下一秒要看到什么动作”，再写口播。
2. 先写场景清单和证明点，再写旁白，不要先写一篇没有画面的文章。
3. “我觉得很酷”必须改成“我点击/驾驶/切换后看到了什么”。
4. “AI 很强”必须改成任务结果、节省步骤或可复现动作。
5. 每 15—30 秒完成一个小闭环：问题 → 动作 → 结果 → 判断。
6. 结尾优先展示最后一个细节或结果，再给 CTA；CTA 只问一个具体问题。

## 可直接套用的口播句式

```text
我先把【真实任务】交给【工具/方法】，想看看它能不能做到【结果】。
你看这里刚刚发生了【具体动作】，这证明【可验证判断】。
我原本以为【预期】，但实际是【结果/限制】。
这个地方我没有让 AI 自己决定，因为【人的判断】仍然需要我做。
我们先去看【下一站】，这里能验证【下一个卖点】。
如果你也遇到【具体痛点】，可以先从【最小动作】开始。
```

## 拍摄前最低证据包

- 结果/成品至少一段无口播素材。
- 原始问题或旧版本一段。
- 关键操作过程 3—5 个屏幕片段。
- 一处失败、返工、限制或对比。
- 一条完整的“从入口到结果”的操作路线。
- 真人开头反应、两段判断、结尾 CTA。
